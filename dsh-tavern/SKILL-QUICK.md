# 角色与故事创作速查

本页用于实际工作时快速定位思路，不能替代 `SKILL.md`。第一次处理一张卡、遇到设定矛盾或需要深入判断时，回查完整版。

## 一、先判断这次在做什么

- **初次读卡**：先浏览核心字段、全部开场和内嵌世界书，再精读当前开场及直接相关条目。
- **设计面具**：先确认当前世界线和开场硬约束，再决定 user 站在故事里的位置。
- **比较方案**：先给 2–4 个真正改变人物动力或相互作用的小样，不急着写完整 persona。
- **讨论剧情**：先回应用户觉得好嗑、平淡、别扭或 OOC 的具体感受，再追人物选择与后果。
- **修改旧面具**：先分辨问题来自初始设定、剧情中已发生的变化、世界书注入，还是模型演绎；不要用 persona 覆盖已经发生的剧情。
- **准备导入**：把幕后设计与未来规划留在 `-design.md`，可导入文件只保留开场时已成立的 persona 正文。

## 二、设计前五问

1. **当前是哪条线？**
   - 使用哪个开场？时间点、关系前提和已发生行为是什么？
   - 哪些是不能否认的硬约束，哪些只是仍可解释的动机？

2. **这张卡真正迷人的是什么？**
   - 撤掉“强、疯、温柔、冷淡”等通用标签，还剩哪些特有的判断、能力、说话方式和亲密模式？
   - 什么场景最容易让 char 作出“只有他会这样做”的反应？

3. **user 为什么偏偏在这里？**
   - user 的身份、欲望、责任、执念或生活如何自然接入当前故事？
   - 为什么是这两个人，而不是给 char 换个同类人物也成立？

4. **故事靠什么继续生长？**
   - 两人的哪些选择会改变局面、认识或关系？
   - 是否有能反复发生但逐渐变化的交集，或一个足够完整的明确终点？

5. **这次想吃什么味道？**
   - 开放参与还是小说观剧？
   - 感情与外部故事各占多重？关系正常还是扭曲？
   - 这些维度彼此独立，不要自动把浓烈等同失智、克制等同寡淡、事业等同冷情。

## 三、三个维度不要混用

### 面具模式：定义到多深

- **开放面具**：写清身份、处境、价值排序与通常取舍；给具体情绪和关键选择留下玩家空间。
- **小说型面具**：可以写明开场时已有的爱憎、执念、偏见、盲区与正在执行的决定；仍不能预写未来变化。

### 人物构型：动力从哪里生长

- **自立展开型**：主要欲望和责任首先从自身生活出发，关系是重要部分但非唯一结构。
- **关系互构型**：爱、恨、信仰、创伤或身份本就与 char 深度相连，关系是人物运转的核心结构。

共同检查：char 暂时不在场时，user 会按自己的欲望、责任或执念做什么？答案可以继续围绕 char，但不能只是静止等待。

### 关系形态：两个人如何运转

- **正常关系**：承认彼此是独立的人，靠持续选择靠近；看点可以来自信任、默契、分歧和共同生活。
- **扭曲关系**：边界受到控制、依赖、投射或权力差侵蚀；不必治愈，但成因、规则与代价必须真实影响选择。

四种组合都能成立。不要拿自立型标准否定恋爱脑，也不要拿健康关系标准要求所有故事必须修复。

## 四、怎样做出真正不同的小样

每个小样至少改变一项核心因果，不只换职业、语气或标签：

- user 最在乎什么，以及为什么；
- 与 char 的既有关系和当前误解；
- user 掌握的资源、责任或限制；
- 两人相互吸引、冲突或共同运转的具体方式；
- 故事主要由感情、事业、任务、日常或世界暗线中的什么推动；
- 故事适合长线积累，还是走向一个明确终点。

小样写到用户能想象“这两个人会怎样相处”即可。每个方案优先包含：

1. 当前处境与人物动力；
2. 只有这对组合容易出现的相互作用；
3. 一个具体、有画面的场景瞬间；
4. 可能的变化方向与适合篇幅。

若两个方案只能靠标题区分，应继续重做。

## 五、人物写法：把标签变成选择

少写抽象评价，多写能跨场景稳定演出的取舍：

- “有事业心” → 即使刚争执，也会先完成不能延期且由他负责的工作。
- “爱得很深” → 他会怎样记忆、照顾、追问、控制、让步或替对方承担后果？
- “冷静” → 在压力下先处理什么，推迟什么，绝不拿什么冒险？
- “强势” → 他在哪些事情上替人决定，又在哪些底线上允许拒绝？

从以下类别挑 2–4 个外显抓手即可：

- 说话节奏、措辞或称呼；
- 压力、亲密和冲突中的反应优先级；
- 与身份和生活相关的具体习惯；
- 有人物意义的底线、雷区或少量微动作。

避免给每种情绪绑定唯一动作，也避免把抓手写成每轮重复的口癖。

## 六、世界书与秘密

- 身份级、从开场起长期相关的条目，可以在 persona 中自然使用准确名称。
- 地点、场景和事件条目，等剧情真正进入时由正文触发。
- 核心规则若应常驻，应检查条目配置，不靠 persona 堆关键词变相常驻。
- 不假定 persona 一定参与关键词扫描。
- 世界书注入不等于角色知识隔离；幕后谜底、隐藏动机和未来真相可能导致模型全知。
- 角色不知道秘密时，persona 只写他经历过的异常、可感知线索和当前解释。

## 七、信息放在哪里

### 可导入 persona：开场初始层

只放开场这一刻已经成立、需要持续影响言行的内容：

- 身份、经历、社会位置与当前处境；
- 与 char 的共同过去、现有关系和当前认知；
- 已拥有的知识、能力、资源与限制；
- 当前欲望、价值排序和稳定行为倾向；
- 开场前已经作出且仍在执行的计划或承诺；
- 少量必要的外显抓手。

### `-design.md` / `plotnotes`：幕后创作层

放读卡依据、二创边界、备选转折、未来走向、结局、风险与世界书策略。

### 聊天记录 / 动态总结：剧情已发生层

放开场后实际发生的新经历、新知识、关系变化和决定。不要倒填进初始 persona 冒充前情。

## 八、常见问题快速诊断

### 很贴设定，但像工具人

检查 user 是否只有“帮助 char / 被 char 影响”的功能；补足自己的欲望、判断、可拒绝之处及主动改变局面的能力。

### 人设很完整，但和谁配都一样

检查 user 的关键选择是否真的会触发 char 特有的价值排序、职业能力、说话方式和亲密模式；减少通用创伤与万能反差。

### 感情很浓，但没有故事

检查爱憎是否会转化成不同选择和后果；浓度不能代替因果链，也不能只靠重复表白、吃醋或受伤维持。

### 事业线很多，但像两张故事拼在一起

让事业责任实际改变相处时间、资源分配、立场与艰难选择；char 也应以自身能力和判断影响外部事件。

### 正常关系太平

不要硬塞秘密或控制。寻找具体分歧、共同责任、生活习惯、信任建立和价值排序差异，让温和互动也产生变化。

### 扭曲关系只剩受害与施害

检查双方如何共同塑造关系、各自得到什么、害怕失去什么、怎样反抗或维持，以及伤害如何留下真实代价。

### 跑起来机械、口癖严重

删减固定动作与绝对措辞，把“每次都会”改成反应优先级或倾向；保留少量能在不同场景变形的抓手。

### 模型提前知道谜底

检查 persona、常驻世界书和动态总结是否注入了幕后答案；改写成公开线索与角色当前解释，或延迟启用完整条目。

### 越跑越不像初始设定

先区分合理人物变化与无因漂移。合理变化写入动态总结；无因漂移再检查上下文、总结和 persona 是否冲突或过于抽象。

## 九、成文前检查

- 当前开场、时间点和世界线是否明确，没有串线？
- 已发生的客观行为是否得到尊重？
- 原设、合理推断和新增二创是否分得清？
- user 的欲望和选择能否成为因果来源？
- 两人的相互作用是否针对这张卡，而非同类角色通用？
- 外部事件是否逼出人物选择，人物选择是否反过来改变事件？
- 设计是否支撑预期篇幅，并允许适时完成？
- 外显抓手是否具体、少量且不会机械重复？
- 世界书使用是否符合条目生命周期，没有关键词堆积或秘密泄露？
- persona 中是否只保留开场时已成立且角色应知的信息？
- 导入正文是否混入分析、风险提示、未来规划或其他世界线知识？

有一项答不上来时，先回到对应章节，不急着润色成文。
